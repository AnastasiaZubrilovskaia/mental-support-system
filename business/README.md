## Права доступа к MongoDB

- **root** создаётся контейнером и нужен только для начальной настройки (`mongo/init.js`) и, при необходимости, будущих миграций. Пароль хранится в `business/mongo/root.env`, приложению он недоступен.
- **Пользователь приложения `business`** имеет роль `readWrite` только на базе `psych_business`. Приложение подключается под ним; база аутентификации — `psych_business`.
- **Секреты** (`.env`, `mongo/root.env`, `secrets/`) не попадают в Git. В репозитории хранятся только примеры файлов.
- **Сеть:** порт 27017 опубликован на `127.0.0.1` только для разработки. В рабочей среде порт не публикуется, доступ только из внутренней сети Docker.
- **JWT:** закрытый ключ только у сервиса аутентификации, сервис бизнес-логики получает открытый.
- **Смена паролей:** `init.js` выполняется только на пустом томе. В разработке — `docker compose down -v` (данные удаляются), в рабочей среде — `db.changeUserPassword()`.
- **Шифрование:** содержимое дневника, показатели устройства и токены календарей планируется шифровать на уровне приложения (AES-GCM), ключ хранить вне БД.

### Что усилить для рабочей среды
- TLS для соединения с БД, резервное копирование и набор реплик.
- Секреты через Docker secrets или Vault, а не `.env`.
- Отдельная учётная запись для миграций (изменение схемы).
- Своя роль вместо `readWrite`: `readWrite` разрешает удалять коллекции, а приложению достаточно `find`, `insert`, `update`, `remove`.
